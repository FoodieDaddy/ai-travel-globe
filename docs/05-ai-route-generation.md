# 05. AI 路线生成设计

## AI 的职责

AI 负责：

- 根据用户需求生成旅行路线。
- 给出城市顺序。
- 给出每个城市停留天数。
- 给出每天行程建议。
- 给出推荐理由和标签。

AI 不负责：

- 最终经纬度可信性。
- 实时价格。
- 实时签证政策。
- 实时天气。
- 真实酒店/机票库存。

## 模型选择

可选：

- OpenAI GPT 系列。
- DeepSeek。
- 通义千问。
- Claude。
- 本地 Ollama，例如 Qwen。

MVP 建议：

- 用云端大模型生成路线。
- 用 JSON Schema 校验。
- 地理编码单独走 API。

## AI 输出格式

必须是纯 JSON，不要 Markdown。

```json
{
  "title": "日本 7 日动漫美食旅行",
  "summary": "这是一条适合动漫、美食和自然风景爱好者的路线。",
  "destination": "日本",
  "days": 7,
  "places": [
    {
      "id": "tokyo",
      "name": "东京",
      "country": "日本",
      "days": 3,
      "lat": 35.6762,
      "lng": 139.6503,
      "description": "适合动漫、购物和城市探索。",
      "tags": ["动漫", "美食", "城市"]
    }
  ],
  "itinerary": [
    {
      "day": 1,
      "city": "东京",
      "title": "抵达东京与浅草探索",
      "items": [
        "抵达东京",
        "浅草寺",
        "秋叶原"
      ]
    }
  ]
}
```

## Prompt 原则

系统提示必须要求：

1. 只输出 JSON。
2. 不要输出解释文字。
3. 不要使用 Markdown 代码块。
4. 城市数量与天数匹配。
5. 每个地点必须有国家。
6. 不确定经纬度可以先给 `null`，后端会补全。
7. 每天行程必须覆盖所有天数。

## JSON 校验

AI 输出后必须校验：

- `title` 必须存在。
- `days` 必须等于用户输入天数。
- `places` 至少 1 个。
- `itinerary.length` 必须等于 `days`。
- 每个 place 必须有 `name` 和 `country`。
- 经纬度如果存在，必须是合法数字。

## 容错策略

### AI 返回 Markdown

尝试提取代码块中的 JSON。

### AI 返回非 JSON

重试一次，使用修复 prompt：

```text
你刚才的输出不是合法 JSON。请只返回合法 JSON，不要解释。
```

### 经纬度错误

后端使用地理编码 API 覆盖 AI 经纬度。

### 城市不存在

地理编码失败时：

- 尝试用英文名。
- 尝试加国家名。
- 仍失败则剔除该地点或提示用户。

## 缓存策略

缓存 key：

```text
hash(destination + days + preferences + budgetLevel + departureCity)
```

缓存内容：

- AI 原始输出。
- 校验后的 plan。
- 地理编码结果。

缓存时间：

```text
AI 结果：1-7 天
地理编码：30 天或永久
```

## 风险

- AI 幻觉地点。
- 行程过密。
- 经纬度不准确。
- 输出格式不稳定。
- 生成涉及高风险地区的路线。

## 应对

- 后端校验。
- 地理编码验证。
- 高风险国家/地区加提示。
- 结果标注“仅供参考”。
- 用户可以编辑路线。
