# 01. 项目约束

## 1. 技术约束

### 前端约束

- 第一版使用 Web 实现，不做原生 App。
- 地球渲染使用 WebGL。
- 推荐 `globe.gl` 或 `react-globe.gl`，不要从零写 Three.js 地球。
- 页面首屏必须能在 3 秒内出现基础界面。
- 地图点位数量 MVP 控制在 100 个以内。
- 一条旅行路线的城市点位建议 3 到 12 个。

### 后端约束

- AI 生成结果必须经过 JSON 校验。
- 后端不能直接相信大模型输出。
- 后端要做超时控制，避免 AI 调用卡死。
- 后端接口必须返回统一响应格式。
- API 请求必须记录日志，但不要记录用户敏感信息。

### AI 约束

AI 只负责生成路线建议，不负责最终事实保证。

必须要求 AI 输出：

- 固定 JSON 格式。
- 城市名。
- 国家。
- 建议停留天数。
- 推荐理由。
- 经纬度，或者由后端二次地理编码补全。
- 每日行程。

必须避免：

- 输出 Markdown 当作业务数据。
- 输出不合法 JSON。
- 生成不存在的城市。
- 生成政治敏感、危险或明显不可行路线。

### 地理数据约束

- 经纬度优先来自地理编码 API，不完全依赖 AI。
- 地点必须有 `lat` 和 `lng` 才能展示在 3D 地球上。
- 相同城市需要做去重。
- 城市名称需要标准化，例如 `Tokyo` 和 `东京` 需要合并。

## 2. 产品约束

- 用户输入不能太复杂，MVP 只保留目的地、天数、偏好、预算。
- AI 结果要可编辑，用户可以修改城市和天数。
- 页面视觉要酷，但交互不能复杂。
- 不承诺价格准确，不承诺签证/安全信息实时准确。

## 3. 安全约束

- 大模型 API Key 必须放后端，不能暴露到前端。
- 地图服务 Token 如必须前端使用，要限制域名和权限。
- 生产环境禁止把管理接口暴露到公网。
- 用户输入需要做长度限制。
- 后端要防止 Prompt Injection 导致系统提示泄漏。

## 4. 成本约束

- MVP 阶段优先使用低成本模型和缓存。
- 同一输入可以缓存 AI 结果。
- 图片资源不要全部从后端转发，尽量走对象存储 + CDN。
- 3D 地球纹理图片要压缩。
- 地理编码 API 要做缓存，避免重复调用。

## 5. 性能约束

目标：

| 指标 | 目标 |
|---|---:|
| 首屏可见 | < 3 秒 |
| AI 路线生成 | < 30 秒 |
| 地球交互帧率 | 尽量 > 30 FPS |
| 单条路线城市数 | 3-12 个 |
| 点位总数 | MVP < 100 个 |

优化原则：

- 不一次性渲染大量 HTML Marker。
- 飞线数量控制。
- 使用懒加载。
- 图片压缩。
- 后端接口加缓存。

## 6. 法务与合规约束

- 不要直接抓取抖音视频里的作者素材和代码。
- 不复制他人私有 UI 设计资产。
- 开源库遵守其许可证。
- AI 生成内容需要标注“仅供参考”。
- 涉及旅游安全、签证、价格时不要做强保证。
