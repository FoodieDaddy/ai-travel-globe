# 10. 实施路线图

## Phase 0：准备

目标：确定需求和技术栈。

任务：

- [ ] 确定前端框架。
- [ ] 确定 3D 地图库。
- [ ] 确定 AI 模型服务。
- [ ] 确定地理编码服务。
- [ ] 确定部署环境。

产出：

- 技术选型文档。
- API Key 准备。
- 基础项目仓库。

## Phase 1：静态 Demo

目标：不用后端，先做出视觉效果。

任务：

- [ ] 创建 React/Vite 项目。
- [ ] 接入 globe.gl。
- [ ] 使用静态 JSON 显示日本 7 日路线。
- [ ] 显示点位。
- [ ] 显示飞线。
- [ ] 左侧行程卡片。
- [ ] 点击城市镜头移动。

验收：

- 打开页面能看到 3D 地球。
- 地图能显示东京、京都、大阪等点位。
- 飞线动画正常。
- 点击卡片能飞到城市。

## Phase 2：后端 API

目标：前端从 API 获取路线。

任务：

- [ ] 创建后端项目。
- [ ] 实现 `POST /api/travel-plans/generate`。
- [ ] 先返回 mock 数据。
- [ ] 实现 `GET /api/travel-plans/:id`。
- [ ] 前端接入 API。

验收：

- 前端不再依赖本地静态数据。
- 后端 mock 路线能正常渲染。

## Phase 3：接入 AI

目标：用户输入后，AI 真实生成路线。

任务：

- [ ] 编写 Prompt。
- [ ] 调用 AI 模型。
- [ ] 强制 JSON 输出。
- [ ] JSON Schema 校验。
- [ ] 错误重试。

验收：

- 输入不同目的地能生成不同路线。
- AI 输出格式稳定。
- 错误能被友好提示。

## Phase 4：地理编码

目标：保证经纬度准确。

任务：

- [ ] 接入高德/Mapbox/Google Geocoding。
- [ ] 城市名转经纬度。
- [ ] 缓存地理编码结果。
- [ ] 经纬度失败时提示用户。

验收：

- AI 只给城市名也能展示在地球上。
- 常见国家和城市定位正确。

## Phase 5：保存与分享

目标：路线可保存、可分享。

任务：

- [ ] 创建 PostgreSQL 表。
- [ ] 保存完整 plan_json。
- [ ] 生成分享 ID。
- [ ] 实现分享页。

验收：

- 生成路线后可以复制分享链接。
- 其他人打开链接能看到同一路线。

## Phase 6：产品化 UI

目标：做得像能发布的 AI 应用。

任务：

- [ ] 美化输入框。
- [ ] 加载动效。
- [ ] 卡片动画。
- [ ] 移动端适配。
- [ ] 空状态和错误状态。

验收：

- 可以录制展示视频。
- 手机和电脑都能看。

## Phase 7：部署上线

目标：公网可访问。

任务：

- [ ] 前端部署到 CDN/静态托管。
- [ ] 后端部署到 ECS/CVM。
- [ ] 配置 Nginx。
- [ ] 配置 HTTPS。
- [ ] 配置数据库备份。
- [ ] 配置日志和监控。

验收：

- 域名可访问。
- API 正常。
- HTTPS 正常。
- 重启服务器后服务自动恢复。
